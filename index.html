DealBuddy 购物搭子

比价的过程应该有记录

你打开十个商品页之后，那些标题、价格、SKU、规格文字和优惠条件不会自动变得可比较。DealBuddy 的 Chrome 扩展从你当前浏览的详情页采集这些字段，发送到只在本机运行的工作台。工作台按你的需求排序，生成选品报告。

下载 Chrome 扩展

从 GitHub Releases 获取最新版扩展 zip（约 19 MB）。MIT 开源。

不接平台 API 不导出 Cookie 不绕验证码 不碰下单与结算

商品信息来自你手动打开的详情页。开启「启用自动采集」后也只在当前浏览的页面工作，不会翻页或打开新标签。报告在本地生成。追问功能需要你在设置里配置外部 LLM Provider。

做法

商品页→扩展→工作台→报告 / MCP

Chrome 采集扩展

扩展从你当前打开的淘宝、天猫、京东商品详情页读取标题、价格、SKU、店铺名和规格文字。

采集分两次投递。第一次把页面可读字段发到工作台，几秒内商品列表就能看到这条商品。第二次在浏览器的隐藏 iframe 中用 PP-OCR 识别详情长图中的文字，完成后按同一链接覆盖更新。图片在浏览器内处理，只有识别出的文字随商品数据发到工作台。

投递地址默认为 http://127.0.0.1:8765/api/current/offers。投递失败时可在扩展弹窗点击「复制 JSON」。

边界：只处理当前打开的页面。OCR 在浏览器本地执行。

本地 Web 工作台

通过 uv run dealbuddy web --port 8765 启动，绑定 127.0.0.1。提供会话管理、商品列表、选品报告和追问区。界面有自动（跟随系统）、浅色、深色三种主题，选择存在浏览器 localStorage 中。

追问需要在「LLM Provider 设置」中配置外部 LLM，填写 Provider 名称、Chat Completions URL、模型名称和 API Key。配置后每轮回答附带三个可点选的追问建议（参数或规格差异、价格或优惠条件、使用场景取舍各一条）。未配置时追问区显示引导，采集和报告正常使用。

边界：无账号体系。会话存 ~/.dealbuddy/sessions，配置存 ~/.dealbuddy/config.json。

Agent Skill（MCP）

工作台在同一端口暴露 MCP endpoint：

POST http://127.0.0.1:8765/mcp

提供 8 个工具：create_session、list_sessions、show_session、set_current_session、add_offer、refine_requirements、get_report、ask_session。skills/dealbuddy 目录有 Agent Skill 集成材料。

边界：请求校验 Origin，只接受 localhost 来源。

报告

工作台在商品入库时自动生成报告。报告包含五个章节：最符合需求、最低预算、综合性价比、值得加预算、不推荐项。有过追问对话后，重新生成报告会在末尾并入「追问记录」章节。

价格口径

字段名含义
标价划线价或标签价格
页面展示价商品详情页当前展示的价格
可见优惠页面上明确显示的优惠信息
估算应付根据页面可直接解析的优惠估算的金额
优惠条件适用前提，如会员、地区、满减、国补或活动期限
复核时间扩展采集该商品信息的时间
数据可信度提取数据完整性评估，值为 high、medium 或 low
价格来自页面可见信息。估算应付只计算页面明确展示且可直接解析的优惠，不代表结算价格。

上手

需要 Python >=3.12、uv 和本机 Chrome。两种方式任选。

方式一：让 Agent 帮你安装

把下面这段话发给你的 Agent（Claude Code、Codex 等能执行命令的都可以）。加载扩展的浏览器操作仍需你手动完成，Agent 会把路径告诉你。

帮我安装并启动 DealBuddy 购物搭子（https://github.com/cyberchen1995/DealBuddy）：
1. clone 仓库，进入目录后运行 uv sync；
2. 用 uv run dealbuddy web --port 8765 启动本地工作台并保持运行；
3. 从 https://github.com/cyberchen1995/DealBuddy/releases/latest 下载 dealbuddy-capture zip 并解压；
4. 告诉我解压目录路径，我会在 Chrome 打开 chrome://extensions，开启「开发者模式」，用「加载已解压的扩展程序」指向它；
5. 完成后提醒我访问 http://127.0.0.1:8765。
环境需要 Python >=3.12 和 uv。安装细节以仓库 README 为准。

装好后 Agent 还能通过 skills/dealbuddy 里的 Agent Skill 直接操作工作台：建会话、读报告、追问分析都走本地 MCP。

方式二：手动安装

  1. 下载并解压扩展

    从 GitHub Releases 最新版下载 dealbuddy-capture zip（约 19 MB），解压到你选择的目录。

  2. 加载到 Chrome

    在 Chrome 地址栏输入 chrome://extensions，打开「开发者模式」，选择「加载已解压的扩展程序」并指向解压目录。

  3. 启动工作台

    git clone https://github.com/cyberchen1995/DealBuddy.git
cd DealBuddy
uv sync
uv run dealbuddy web --port 8765

    在浏览器访问 http://127.0.0.1:8765，新建一个购物研究会话即可开始。

数据边界

  • 工作台服务绑定 127.0.0.1，外部网络无法访问
  • 不需要注册或登录
  • 会话文件保存在 ~/.dealbuddy/sessions，配置保存在 ~/.dealbuddy/config.json
  • 详情图在浏览器扩展的隐藏 iframe 中做 OCR，图片本身不经过工作台传输
  • 外部请求只在配置并启用 LLM 后发生（追问、商品短评、报告再生成），数据去向由你配置的 Provider 决定
  • API Key 写入 config.json 后不出现在接口响应或日志中，界面用掩码显示
  • 扩展不读取购物平台的 Cookie
  • MCP 请求校验 Origin，拒绝非 localhost 来源

常见问题

哪些页面可以采集？

淘宝、天猫、京东的商品详情页。搜索列表、活动会场、购物车和结算页不在处理范围内。

估算应付是实际结算价吗？

不是。估算应付只计算页面上明确展示且可直接解析的优惠。实际结算金额可能受会员等级、配送地区、库存变动和平台实时活动影响。

不配置 LLM 能用吗？

采集、排序和报告都在本地完成，不依赖 LLM。追问功能需要配置外部 LLM Provider。未配置时追问区不可用，其他功能正常。

自动采集会批量打开页面吗？

不会。自动采集只在你当前浏览的页面触发，不会打开新标签，不会翻页。在扩展弹窗中可以随时关闭。

OCR 识别为什么比较慢？

主要时间消耗在 PP-OCR 的 JavaScript 前后处理（图片缩放、检测框提取、逐行识别输入准备），不在 ONNX 推理环节。两阶段投递让商品在 OCR 完成前就能显示在工作台。

会话数据保存在哪里？

~/.dealbuddy/sessions/ 目录，每个会话一个 JSON 文件。设置 DEALBUDDY_HOME 环境变量可以指定其他根目录。
